koota-kit is deliberately **not a game engine**. It is the narrow layer that
prevents recurring classes of simulation bug without hiding
[Koota](https://github.com/pmndrs/koota)'s queries, entities, relations, or
actions.

## Why use it?

<CardGrid stagger>
	<Card title="Two independent RNG streams" icon="random">
		World generation and runtime events never share a PRNG instance, so
		unrelated gameplay draws can't perturb world content. See
		[Randomness has two jobs](/koota-kit/getting-started/#randomness-has-two-jobs).
	</Card>
	<Card title="Byte-exact snapshots" icon="seti:lock">
		`snapshotWorld` and `restoreWorldHeader` round-trip the clock and both RNG
		states through JSON, so a loaded save reproduces the next random result.
		See [Persistence boundary](/koota-kit/getting-started/#persistence-boundary).
	</Card>
	<Card title="Safe object-valued traits" icon="approve-check">
		`defineTrait` rejects bare object and array fields at compile time and
		runtime, so state can't alias across entities. See
		[Object-valued traits need factories](/koota-kit/api/#traits).
	</Card>
	<Card title="Single-consumer event logs" icon="document">
		`drain` consumes once, `peek` never consumes — so a HUD or test can't
		steal an event from the system that owns it. See
		[Event logs have one consuming owner](/koota-kit/api/#eventlog).
	</Card>
</CardGrid>

## Install

```sh
pnpm add @jbdevprimary/koota-kit koota
```

Requirements: Node.js 22 or newer, and Koota `^0.6.6` as a peer dependency.
The package ships native ESM and CommonJS entry points with format-correct
TypeScript declarations.

Continue to [Getting started](/koota-kit/getting-started/) for a full
walkthrough, or jump straight to the [API reference](/koota-kit/api/) and
[architecture notes](/koota-kit/architecture/).
